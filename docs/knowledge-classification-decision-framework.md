# 知识分类判断框架

更新日期：2026-11-13

本文件是 FinLens 知识分类的**通用判断入口**。术语词表、历史案例和领域细则用于辅助，不替代本文件的判断顺序。

## 一、三个独立维度

分类时始终分开处理以下三件事：

1. **category：知识本体**
   - `finance`：金融术语。
   - `background`：背景层。
   - `method`：分析方法。
2. **cardType：解释形式**
   - `concept`：定义、指标、制度、工具、身份或角色。
   - `phenomenon`：可观察事件、趋势或结果。
   - `mechanism`：因果链、传导路径或制度运行逻辑。
   - `method`：可执行、可重复的分析程序。
3. **categories：板块归属**
   - 主分类只能一个。
   - 可有一个交叉板块。
   - 交叉不等于两个概念偶然同时出现。

`cardType=mechanism` 不表示 `category=method`。因果链可以存在于金融术语、背景层或分析方法中。

### 案例字段边界

`cases` 是解释材料，不是分类证据。分类时必须忽略案例中的金融、法律或技术词，只根据术语主对象、`one`、`body` 和完整方法程序判断。

案例优先使用可核验的真实事件、政策、市场数据或原文语境；无法核验时留空。数字必须带期间、单位和口径，假设数字必须明确写“假设/示例计算”。案例不得编造机构、日期、数字或因果结论，也不得把一个案例写成普遍规律。

案例质量与正文错配分开提示，但可以在同一个“查看建议正文/案例”确认窗口中审阅；未经用户确认，不得自动覆盖。

## 二、核心判断对象

每张卡先回答一个问题：

> **这张卡主要在解释什么对象？**

不要用文章主题、媒体类型、术语所在段落的话题或模型的初始标签替代这个问题。

可用四个检验：

### 1. 主解释对象检验

- 卡片定义的是金融资产、合约、机构、融资关系或定价关系吗？
- 还是法律程序、技术系统、消费趋势、产业结构、公司治理或分析方法？

### 2. 后果检验

金融影响是结果，还是本体？

- “失信影响授信”是金融后果。
- “失信被执行人”是司法身份。
- 前者可形成交叉，后者默认背景。

### 3. 反事实检验

移除金融后果后，该对象是否仍然成立？

- 移除“可贷款”后，“CEO”仍然是 CEO。
- 移除“可交易”后，“履约保证”仍然是金融合约。

### 4. 平行领域检验

把同一结构放进另一个行业，是否仍然属于同类对象？

- “品类扩张”“市场细分”“复购率”在食品、服装和软件行业都存在，默认是经营与营销背景。
- “股权融资”“信用利差”“证券化分层”跨行业仍属于金融本体。

## 三、正证据原则

分类必须由**主解释对象的正面证据**支持。

- 金融术语需要金融本体证据。
- 分析方法需要完整程序证据。
- 背景层是默认安全层。

模型的原始 category 只是弱提示，不是保护伞。缺少金融本体或完整方法程序时，即使模型写的是 `finance` 或 `method`，最终也应归 `background`。

### 金融本体证据

主要解释对象至少命中一类：

1. 货币、信用、利率、汇率或支付。
2. 金融资产、合约、工具或证券化结构。
3. 银行、保险、基金、券商、评级或金融基础设施。
4. 融资、资本结构、资本成本、资本预算或项目融资。
5. 估值、资产定价、收益率、利差、风险溢价或流动性。
6. 投资组合、资产配置、承保、风险转移或金融风险计量。

“资产”“价格”“市场”“投资”“回报”“风险”“funding”等泛词只提供候选信号，必须结合主解释对象。

### 背景层范围

- 政治、法律、司法、监管环境、公共治理。
- 产业组织、竞争战略、供应链、产能和实体投资。
- 技术、AI 系统、工具、平台、科研基础设施。
- 消费趋势、产品品类、营销、品牌和消费者行为。
- 医药、生物科技、健康服务和科研活动。
- 公司治理、管理角色、组织与经营流程。
- 民事执行、失信惩戒、财产查控和司法处置。

### 方法程序证据

方法候选需要在以下六类证据中至少满足五类，并强制包含分析目的、输入、变换步骤和输出解释：

1. 明确分析目的。
2. 明确假设或模型设定。
3. 明确输入数据、变量或情景。
4. 明确计算、估计、检验、模拟或推断步骤。
5. 明确输出结果及解释/决策规则。
6. 明确适用边界、误差或验证方式。

同时满足：

- `cardType=method`；
- 至少两个可执行 `methodSteps`；
- 方法可以迁移到不同数据或案例。

术语名含 `model`、`framework`、`agent`、`analysis`、`method` 不构成方法证据。

中文证据与英文证据同等有效。“核查、比较、计算、排序、汇总、映射、剔除、筛选、判断、验证”等程序词，以及明确的输入、输出和口径边界，都计入方法证据。

金融估值是特殊情形：`relative valuation`、`相对估值`和可比公司估值主分类属于 `finance`；只有同时给出完整计算分析链时，才交叉归入 `method`。该交叉不能推广到其他金融概念。

## 四、判断顺序

按以下顺序执行，先满足先停止：

### 第 1 步：方法程序检验

卡片是否主要解释一个可重复的分析程序？

- 是，且主要对象是金融估值：`finance + method`。
- 是，其他可迁移程序：`method`。
- 否：进入第 2 步。

注意：

- 有流程不等于有方法。
- 有因果链不等于有方法。
- 有风险传导不等于有方法。
- “个人故事不能替代基本面”可以形成证据核验方法；“个人故事”本身仍是背景现象。

### 第 2 步：金融本体检验

卡片的主解释对象是否是金融资产、合约、机构、融资、资本市场、估值、保险、投资或金融风险？

- 是：`finance`。
- 否：进入第 3 步。

注意：

- 消费趋势、营销概念、品牌资产、复购率、医药类别和 CEO 不因文章属于财经媒体而成为金融。
- 战略收购、并购、自筹资金、融资和资本结构属于金融。
- `brand equity` 是营销资产；`brand equity valuation` 才可能同时进入金融/方法。

### 第 3 步：交叉分类检验

主对象属于背景层，但卡片是否同时、实质性地解释了金融关系？

- 例：金融法律、金融监管、金融科技、AI 市场重定价、失信对银行授信的影响。
- 例：`divorce asset division` 主对象是婚姻财产法下的归属与分配机制；只有正文同时实质分析信托持有股份的估值、流动性、控制权、税务或披露时，才以 `background` 为主并交叉 `finance`。
- 例：`geopolitical risk premium` 说明地缘政治条件被转化为收益率、折现率或风险价格补偿时，金融为主并交叉背景。
- 是：主分类 `background`，交叉 `finance`。
- 否：进入第 4 步。

交叉需要两个对象都能独立成立：

1. 一个可以明确命名的背景本体。
2. 一个可以明确命名的金融关系。

只有金融后果、类比或一句融资评论，不自动构成交叉。

外生条件型风险溢价还要再问一次“解释重心在哪里”：

- 主要解释外部条件如何形成收益率、利差、折现率或保险价格补偿：`finance + background`。
- 主要解释外部条件本身或只有笼统市场影响：`background`，不要因为 `premium` 词形强行交叉。
- 主要解释溢价的公式、估计、数据口径或计量程序：`finance` 或 `method`。
- 只出现 `risk`、`premium`、`price`、`leverage` 或 `investment`：不能单独构成交叉。

### 第 4 步：背景层

无法形成金融本体或完整方法程序时，归 `background`。

这是默认层，不是“分类失败”。背景层承担解释金融活动的外部条件、产业环境和技术、法律、消费与治理对象。

## 五、易混淆概念矩阵

| 信号 | 背景层 | 金融层 | 方法层 |
|---|---|---|---|
| `model` | 模型软件、平台、科学模型、具体实现 | 金融模型作为产品/工具对象 | 有假设、输入、步骤、输出与边界的分析程序 |
| `risk` | 政治、法律、合规、战略、声誉、一般运营风险 | 市场、信用、流动性、承保、交易对手、监管资本风险 | 风险计量、压力测试、情景分析 |
| `premium` | 外生条件型风险溢价中的背景条件本体 | 股权风险溢价、期限溢价、信用利差、保险保费 | 溢价估计、定价模型、风险计量程序 |
| `leverage` | 谈判杠杆、议价能力、政策博弈筹码 | 财务杠杆、杠杆收购、保证金与融资结构 | 杠杆测算、情景分析、资本结构模型 |
| `asset` | 可执行财产、品牌资产、实体资产、科研资产 | 金融资产、资产定价、资产组合、证券化资产 | 资产估值或回收率计量程序 |
| `divorce / marital property` | 婚姻财产认定、法院分配、婚前协议、信托权益归属 | 当事人对可定价证券或企业权益的经济暴露、估值、流动性与处分权 | 明确给出估值、折现、流动性或控制权计量程序时再考虑方法 |
| `jointly controlled equity` | 信托、受托人和共同治理造成的控制权分散 | 股权资产、投票/投资权、减持、披露与估值 | 只有控制权价值或估值本身构成完整分析程序时才进入方法 |
| `capital` | 产业资本、人力资本、社会资本等非金融用法 | 资本结构、资本成本、资本预算、监管资本 | 资本配置或资本成本测算方法 |
| `recovery` | 司法追缴、普通资产处置 | 不良资产回收、债权回收、回收率、LGD | 回收率或 LGD 测算模型 |
| `agent / AI` | AI agents、agentic workflow、模型平台 | — | agent-based modeling、multi-agent simulation 且需完整程序 |
| `policy` | 产业、社会、司法、一般公共政策 | 货币政策、金融监管、资本约束 | 政策评估、成本收益分析等程序 |
| `consumer / brand` | 消费趋势、品类、品牌、营销、复购 | 消费信贷、消费金融、消费资产证券化 | 消费者调查、UPC 销售追踪、证据核验程序 |
| `executive / CEO` | 管理角色、公司治理 | CEO 薪酬证券化等明确金融合约才进入金融 | 高管激励模型等完整程序 |
| `valuation` | 环境价值、社会价值等非金融价值判断 | 相对估值、可比公司估值、资产或企业估值 | 金融估值同时具备可比对象、计算和边界时 `finance + method` 交叉 |

## 六、判断公式

```text
金融估值对象 + 完整计算分析程序
  -> finance + method

完整方法程序
  -> method

否则，外部条件本体明确且可识别定价补偿关系
  -> finance + background

否则，金融本体明确
  -> finance

否则，背景本体明确且金融关系实质存在
  -> background + finance

否则
  -> background
```

### 条件式规则

- `market correction` / 股市修正：对象是股票、指数、证券组合或其他金融资产从近期高点回撤时，归 `finance`；若是房地产、一般商品或产业价格修正，且没有金融资产定价关系，归 `background`。
- `circular financing` / 循环融资：投资、采购、云或算力承诺、供应商融资、应收应付和再融资形成实质资金闭环，并影响现金流、融资或信用暴露时，归 `finance + background`；没有融资关系的商业合作或纯会计循环归 `background`。
- `capital expenditure` / `capex`：单独描述实体投资或会计分类时归 `background`；主解释对象是 capex 对经营现金流、自由现金流、融资缺口、流动性、偿债能力或资本成本的影响时，归 `finance + background`；只有完整可复现的现金流比较计算程序才归 `finance + method`。
- `purchasing power` / 购买力：衡量货币单位可购买的实际商品与服务时归 `finance`；若卡片完整说明商品篮子、价格数据、支出权重、指数计算和实际值平减程序，则归 `finance + method`。单纯的社会生活成本或抗议背景不替代购买力指标本体。

### 分类重新核验的证据闸门

重新核验预览必须从 `one` 和 `body` 提取原始片段，并分成三类：

1. **主对象证据**：说明卡片主要在解释什么，至少有一个可读、非空洞的定义或解释片段。
2. **独立交叉证据**：支持第二板块的独立片段，不能只是术语名、来源目录或主对象片段中的泛词。
3. **明确否定证据**：包含“不涉及、不包含、没有、无需、并非、而不是、不构成”等否定语义的片段，不得进入正面证据。

规则名称和关键词命中只产生候选，不直接产生修改建议。若主对象证据不足，或提出交叉分类却没有独立交叉证据，应保留原分类、将置信度降至不超过 `65%`，并保持未勾选。来源目录和检索结果只用于后续核查，不单独作为分类证明；正文与术语明显错配时保留分类候选，但必须进入人工确认。

## 七、置信度

- `0.98`：主词和描述都明确指向本体。
- `0.95-0.97`：领域明确，存在轻微歧义。
- `0.85-0.94`：上下文支持，但术语本身可能有多种含义。
- `0.75-0.84`：模型与上下文一致，但没有强本体规则。
- `0.70`：模型给出了金融或方法标签，但正文没有正面证据，按背景兜底。
- `0.50`：描述不足，无法可靠判断。

低置信度不改变默认背景原则。`finance` 和 `method` 都需要正面证据。

## 八、新增规则时的维护方法

1. 先判断现有框架能否直接处理。
2. 只有新对象暴露了真实语义缺口时，才增加规则。
3. 新规则优先表达**对象类型**，其次才写具体词。
4. 同时添加：
   - 一个正例；
   - 一个近似反例；
   - 一个未见过的新词。
5. 避免把一个词的偶然金融后果写成全局金融触发词。

## 九、完成检查

每张知识卡分类前确认：

- 我判断的是主解释对象，不是文章主题。
- 我没有用模型标签替代证据。
- 我没有把金融后果当成金融本体。
- 我没有把机制、流程或传导链当成方法。
- 交叉分类的两边都能独立成立。
- 没有正面金融或方法证据时，已使用背景层。
