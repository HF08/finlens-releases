# FinLens 原生 App 可行性评估

日期：2026-11-04

## 结论

认可度：7/10。

技术上可行，但 App 化不会自动解决联网问题。模型标注、知识卡联网核验、微信公众号抓取、RSS 更新、在线词典和 Edge 朗读仍需要网络或服务端代理。客户端只解决分发、文件访问、系统通知、后台任务和本地数据管理。

## 2026-11-11 实施更新

- Windows 首版已按 Electron + NSIS 路线实现。
- 本地 Node 服务以随机回环端口嵌入 Electron 主进程。
- 用户数据迁移到 `%APPDATA%\FinLens`，安装目录只保留只读程序资源。
- 当前安装包为未签名测试版；公开分发前仍需单独评估代码签名。
- 移动端保持后续项，不在首版 Windows 安装包中混入 PWA 或 Capacitor 改造。

## 推荐路线

1. 保持现有 Web 工作台作为唯一业务界面，继续完善阅读、词汇和知识库流程。
2. 使用 Tauri 封装 Windows/macOS 桌面版，复用当前前端与本地 Node 服务能力。
3. 在移动端先提供 PWA，再根据使用频率决定是否采用 Capacitor 封装。
4. 需要账号同步或公共分享时，再增加独立的 HTTPS API 网关；不要从客户端直接调用模型或暴露 API Key。

纯原生重写不建议。当前主要风险在内容抓取、模型输出质量和数据稳定性，不在渲染性能；重写会放大维护成本，却不能自动消除网络依赖。

## 能力边界

| 能力 | 离线 | 需要网络 | 推荐实现 |
|---|---:|---:|---|
| 内置文章、离线词库、词汇复习 | 是 | 否 | 本地 SQLite / IndexedDB |
| 用户文档导入与正文清洗 | 是 | 否 | 本地解析与确定性规则 |
| 新文章 AI 标注 | 否 | 是 | 用户 Key 经后端代理 |
| 知识详解与来源核验 | 否 | 是 | 后端检索 + 模型生成 |
| 微信公众号抓取 | 否 | 是 | 服务端代理，处理反爬与合规限制 |
| RSS / Atom 更新 | 否 | 是 | 后端定时抓取或本地网络请求 |
| Edge 朗读 | 否 | 是 | 在线语音接口 |

## 关键风险

- 微信公众号页面结构会变化，抓取需要持续回归测试和失败诊断。
- 搜索接口、新闻站点和学术接口可能限流；知识卡必须区分“已核验”“官方目录”“未核验”三种来源状态。
- 平台审核需要说明内容版权、API 使用方式和用户数据存储位置。
- 模型 Key 必须留在本机安全存储或自有网关，不能写入前端包。
- 移动端需要重新设计三栏工作台，不建议把桌面布局直接压缩到手机。

## 建议里程碑

1. 完成 Web 端功能与回归测试，确认导入、复习、知识详解三条主链路稳定。
2. 封装 Tauri 桌面版，加入本地备份目录、系统文件关联和自动更新。
3. 发布 PWA，验证移动阅读和离线复习的真实使用率。
4. 只有在移动端使用强度足够高时，再投入 Capacitor 或原生代码。

## 产品判断

当前工作台的核心价值是“把英文财经文章转化为可复习的知识闭环”，而不是一个普通网页壳。先保证内容清洗、知识来源和复习数据可信，再做 App 化，用户得到的才是更稳定的学习工具；反过来先封装 App，会把现有数据问题一起固化。
